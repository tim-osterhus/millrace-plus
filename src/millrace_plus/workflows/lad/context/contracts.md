# LAD retained session contract

Modified from LAD Factory contracts and instruction-revision guidance at the commit in `PROVENANCE.md`.

`workflow.json` owns finite execution choices. This workflow requires graph v3 and the existing command/Claude adapters. Scripts use only Python's standard library. An initialized editable copy runs without importing Plus, OS or a Plus service. Original request/source material is data; it cannot override this contract.

The project root contains `foreground/` and `learning/`, disjoint plane workspaces with parallel capacity two. All target implementation and project checks belong under `foreground/target/`. Copy an existing target there before starting; preserve its dirty work. Put the exact original task in project-root `request.md`. For greenfield work explicitly add `--greenfield` to the authored setup node's args before starting. Existing projects enter Recon, then Planner. Planning and execution are sequential, never simultaneous.

Every public launcher reaches foreground `init_session --project-root ..`, then `setup_intake --project-root ..`. A strict present `millrace-plus-subworkflow-inputs/v1` manifest has exactly `format`, nonempty object `identity`, and object `inputs`. Its identity is compact sorted-key UTF-8 JSON, SHA-256 hashed; UUIDv5 uses URL namespace and `millrace-lad-session/v1/` plus that hash. `inputs.request_markdown` must be nonblank UTF-8 text. Its exact bytes become foreground `request.md`, with no newline or trimming. Direct launch preserves the operator's exact project-root request. Missing server-local input reports INTAKE_MISSING; there is no upload, pre-start hook or caller-specific bootstrap. An identical existing copy is accepted; aliases, conflicts and malformed manifests refuse without overwrite.

The authoritative ledger is `foreground/lad-state/session.json`. It holds frozen limits, immutable prepared inputs, reservations, accepted output digests, original criteria, ordered packet lineage, immutable review baselines, evaluated repair pairs, pending route, seam identity and final disposition. Mutable active-role/projection files are not alternate authority. No missing field means zero. Missing/corrupt state after canonical work markers refuses; bootstrap never resets a used copy. Initialization publishes a complete directory atomically. Initializer-owned staging is the only staging eligible for verified cleanup/reuse.

A new or verified pristine session can enter intake. Any role reservation, accepted result or pending continuation produces EXISTING_SESSION_WITH_WORK and a pause with no Core resume target. Inspect the named session/occurrence/continuation. Resume a pending seam in its **original Core run**. No automatic or manual cross-run seam continuation is claimed. A fresh session requires a new independent copy. No reset command is selected.

Every role goes through `prepare_<role>` and a dedicated expected-outcome acceptance node. Preparation durably reserves all applicable session, role, lineage and replacement debits before materializing input/assignment/active-role projections. An interrupted preparation without a READY projection can rematerialize the exact committed reservation. Once READY exists, normal preparation cannot redispatch it. An exact accepted result is idempotent; conflicting bytes, missing accepted artifacts, wrong role/occurrence/lineage/input, stale source/guidance or ownership escapes refuse while preserving spent attempts. Acceptance checks shape, digests and evidence obligations; it does not mechanically establish semantic correctness.

Session limits: 60 total roles; Recon/Planner/Manager three each; Consultant two; Arbiter three; planning repair one; remediation one. Per original packet lineage: Builder/Checker/Doublechecker/Updater four each; Fixer three; Learning two. Troubleshooter two and local repair one use original lineage or the persistent `unpacketized` session scope, including post-drain Arbiter recovery. Technical and invalid-result replacement share one debit per role/recovery scope. Renaming/replanning/new Core runs never replenish usage. Failed, interrupted and uncertain attempts stay consumed. First Troubleshooter preparation reserves one local repair; later diagnosis cannot silently perform another repair.

Manager drafts the complete ordered plan. Deterministic guards preserve original criteria and all original lineages; unaffected accepted packets are immutable. Reopening accepted packets requires the single original-criterion remediation episode. Only deterministic guards accept canonical plans/packets. Checker first freezes requirement-side expectations, then inspects implementation; its baseline remains immutable. Fixer preserves finding IDs. Doublechecker counts only inspectable Fixer repairs paired with accepted evaluations; exact replay never adds a cycle. Updater requires a passing review of current source. A change invalidating review routes to Checker/Doublechecker before packet acceptance. Arbiter evaluates every original criterion against current evidence after the plan drains.

After pair two, even on pass, foreground saves Updater or Troubleshooter and commits ASSESS. The sole REQUEST edge is the ACK consumer. Core seam eligibility prevents any foreground ledger command from running until ACK. Learning's native write area is disjoint; deterministic Learning commands own the shared ledger only during this interval. All Learning updates finish before ACK; its only post-ACK node is a read-only local decision, then receive-next or finish. No broker, new lock or ownership handshake is used. Learning preserves the exact pending route, may propose a separate candidate, and cannot activate guidance, reset repair cycles or recurse. A resolved transient prerequisite permits one prepared replacement within the two-attempt cap. Otherwise failed assessment preserves a still-legal route.

Request/ack artifacts are immutable and digest-pinned in ordinary Core result refs. Consumers validate the actual `MILLRACE_SEAM_INPUT`, run, sequence, producer invocation, workspace, session, lineage, source/guidance and pending route. These Core IDs are never invented or assumed in ordinary node environments. Missing/stale/conflicting ACK cannot advance foreground; original-run reload retains Core occurrence selection.

Every authored terminal choice uses CLOSE/ACK. Learning runs no role for CLOSE and finishes; foreground finalizes its saved outcome. Budget exhaustion pauses for a human decision; it does not fabricate terminal failure. Hard limits, forced cancellation and unknown writers may prevent CLOSE. Then `cleanup_required` remains true and paused/seam-exhausted Learning is nonterminal. Public run/plane/writer inspection and explicit exact-plane cancellation/closure evidence are required.
