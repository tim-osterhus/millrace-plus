# LAD software factory workflow

An editable twelve-role graph that moves from existing-project Recon through planning, sequential packet implementation/review, a bounded Learning gate and original-criteria arbitration. Role responsibilities derive from pinned LAD Factory Markdown; see `PROVENANCE.md` and `provenance.json` for all 44 source dispositions and the unchanged Apache-2.0 license.

Initialize with `millrace-plus catalog init bundled:lad PATH`, then operate the copied `workflow.json` with the same public controls as any other graph. Put the task in project-root `request.md`, preserve its bytes, and put the existing target under `foreground/target/`. Both `foreground/` and `learning/` must exist in that project. For greenfield work explicitly add `--greenfield` to the setup node's args before starting. Check the pinned native binding/profile and your separate launch allowance first. An initialized copy's scripts need only Python's standard library; no Plus service or import is required.

Direct CLI/OS/MCP, subworkflow and Paperclip callers all reach the same graph-owned bootstrap and intake. A strict existing assignment manifest supplies exact request_markdown bytes; direct launch requires server-local request.md. There is no upload or pre-start hook. Missing input pauses honestly. The graph does not create acceptance criteria from missing input.

The graph, `context/contracts.md`, `context/role-contracts.md`, and `context/routes.md` define routing, artifacts and finite session accounting. `foreground/lad-state/session.json` is authoritative. Native roles write occurrence results; deterministic preparation/acceptance guards reserve debits, verify useful evidence, preserve immutable accepted artifacts and expose finite graph outcomes. No role scheduler, Core primitive, Core retry or runtime dependency is added.

Planning and Execution share one sequential foreground plane. Learning starts seam-blocked. After the second actual Fixer→Doublechecker pair, even on pass, foreground saves its route and waits for exact Learning ACK. Native write areas are disjoint; deterministic ledger writes serialize through REQUEST/ACK graph eligibility. Capacity is two, but this mandatory gate makes no claim of actual overlap. Candidates remain inactive in Learning's separate area.

The independent Core limits are 609 invocations and 35,900 elapsed seconds, command timeout 10 seconds and native timeout 1,800 seconds. Derivation: 2 initialization/intake + 3×60 prepared/native/accepted role nodes + 2×60 domain decisions + 5×60 ASSESS seam nodes + 1 denied guard + 6 reserved CLOSE nodes = 609. The elapsed cap does not promise 60 worst-case native timeouts fit. Repeated manual deterministic redirects are outside this automatic-path bound; inspect remaining Core capacity before continuation. The workflow's 60-role cap grants no native calls or spending.

A used copy never resets or automatically replans. Its bootstrap pauses without a resume target and names the retained continuation. Resume/recover pending waits in their **original Core run**. Follow `context/harness.md` for explicit prepared replacement, terminal-failure intent, CLOSE/ACK and hard-stop cleanup. A fresh session uses a new independent copy. Preserve all spent/uncertain attempts and accepted artifacts. Raw generic native retry is outside the LAD accounting guarantee.

Offline command peers verify domain routes and useful code/Markdown artifacts. Native/provider qualification, live Paperclip account operation and remote MCP deployment require separate accepted evidence and authorization. Paperclip/MCP transport success is not LAD semantic acceptance. No commits, publication, deployment or messages follow from a role recommendation.
